# WF-M08-04 — Invoice roll-back (delete undelivered invoice) and legacy return-invoice with freeze stock

**Confidence:** CONFIRMED for `sp_Delete_ProformaInvoice` (body read) and PAGE-290; `sp_DeleteDeliveryInvoice` body UNKNOWN.

## Part A — Delete an undelivered invoice (PAGE-288)
### Trigger & actors
Operations user must cancel an invoice generated by mistake before delivery confirmation.
### Preconditions
`tblInvoice.InvoiceNo` exists, `DelivaryInvoiceNo IS NULL`, not an adjust invoice (page check `HasProforma`).
### Steps
1. Tick "Invoice", type number, blur → `chkProforma` (`HasProforma`).
2. Delete + confirm → `ProformaOrInvoiceReturnBLL.DeleteProforma` → `DeleteProformaDal` → `sp_Delete_ProformaInvoice(@InvoiceCode,@User=LoginName)`.
3. SP loops invoice details: delete matching negative 'Issue' row in `tblDCStore`; clamp inflated Receive row; write `tblProInvoiceReturnTrack`; copy to `tblInvoiceDetail_DeleterRecord`; delete `tblInvoiceDetail`.
4. After loop: `tblOrderDetail.Status=NULL`, `tblOrder.IsInvoice=0`; delete `tblReturnAmount` rows of the invoice; delete `tblInvoice`; write `tblInvoiceDeleteLog`.
### Data changed
tblDCStore (DELETE Issue rows; UPDATE Receive rows StockQty=TotalQuantity where inflated), tblProInvoiceReturnTrack (+), tblInvoiceDetail_DeleterRecord (+), tblInvoiceDetail (−), tblOrder/tblOrderDetail (reopen), tblReturnAmount (−), tblInvoice (−), tblInvoiceDeleteLog (+).
### Stock effects
Stock reservation released by **deleting the negative Issue ledger row** (matched on `ReferenceDCStoreId`, `Trans_Type='Issue'`, `StockQty=−TotalQuantity`, `DELETE TOP (1)` per detail). Receive row is not incremented (fix of an earlier bug; see `sp_Adjust_DCStore_Stock_Only`).
### Valuation / accounting
None reversed here (no posting SP call) — if the invoice had created delivery COGS/AR entries they are not touched (invoices deletable here have no delivery number, so normally none exist; INFERRED).
### Branches
Not eligible → page message; SP ineligible → silent no-op yet "Delete successfully"; mid-loop failure → partial deletion (no transaction). Hidden "Delivery" mode: refuses if freeze stock consumed (BR-M08-054) else `sp_DeleteDeliveryInvoice` (UNKNOWN).
### Postconditions
Invoice gone; order can be re-invoiced; audit rows exist.
### Related BR ids
BR-M08-050…054. **Pages:** PAGE-288.
### Tests

## Part B — Legacy return invoice from a delivery invoice with freeze stock (PAGE-290)
### Trigger & actors
User returns selected lines of a delivery invoice using the older page.
### Steps
1. Enter delivery invoice no + DC → `Button1_Click` → `LoadDelivaryInvoice`, `GetQty` (previous returned qty).
2. Tick lines, enter RQty (≤ TQty − PRQty) → `dQtyTextBox_TextChanged`.
3. Invoice Generate → `InvoiceBLL.SaveReturnInvoice(Invoice)` (number `INV-<unit>-<count+1>`) → `tblReturnInvoice`; per ticked line `SaveReturnInvoice(detail)` → `tblReturnInvoiceDetail` (`ReuturnInvoiceDetailId`); `SaveDCStoreFreeze` → `tblDCStoreFreeze` (StockCondition 'ReturnStock').
### Stock effects
`tblDCStoreFreeze` +1 row per line (StockQty=RQty). **`tblDCStore` unchanged** — returned goods are quarantined, not available for sale.
### Valuation / accounting
None; no vouchers.
### Defects
Saved detail amounts use delivered qty (BR-M08-042); no ticked-row check; count-based invoice number (BR-M08-044).
### Related BR ids
BR-M08-040…045. **Pages:** PAGE-290; interacts with PAGE-288 guard.
### Tests
PAGE-290 §27 T1-T7.
